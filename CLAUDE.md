# CLAUDE.md: trivia game

Read this, `PROGRESS.md` and `DECISIONS.md` (if they exist) and the files in `docs/` at the start of every session. Files in
`docs/extra/` are later notes and take priority over the numbered docs when they disagree.

## What this is

A mobile map-and-flag trivia game for iOS and Android. It is the playable version of our viral TrendForge
trivia videos, and its job is to turn video viewers into players who come back every day. You work on your own: nobody
answers questions, reviews or play-tests during the build. You are the game designer, the developer and the
tester, the docs are the knowledge to judge by, and the quality bar is yours to hold.

## The standard

The result must feel like a game, not like a quiz app. Concretely, that means every item of the checklist at
the end of `docs/04-FEEL-AND-UI.md` passes. A feature that works but has no feedback, sound or motion is not
finished. Depth before breadth: one mode that feels great beats five that work.

## Stack (decided)

- React Native + Expo (development build, not Expo Go, because ads and purchases need native code),
  TypeScript, strict mode. Expo Router for navigation.
- Map and flag drawing: React Native Skia (the video studio also draws with Skia, so the look carries over).
- Animation: Reanimated. Haptics: expo-haptics. Sound: Expo's audio module, with sounds preloaded.
- State: a small store (Zustand) saved to fast local storage (MMKV). The game works fully offline; no
  account, no backend in version 1.
- Ads, purchases, analytics and remote config each sit behind one small interface in `src/services/`, with a
  fake implementation used until real keys exist. Game code never calls an SDK directly.
- Look up the current docs for every library before installing or using it. Versions and APIs move.

## Rules

- All tuning numbers (rewards, prices, timers, XP curve, ad pacing, level definitions) live in
  `src/config/balance.ts` and `src/config/levels.ts`, never in components. `tools/balance_sim` reads the same
  values. Changing balance must never need a code change elsewhere.
- All colours, fonts, radii, shadows and motion timings live in `src/theme/`. Components take them from there.
- All user-facing text goes through one strings file so it can be translated (English first; Turkish, Spanish
  and Portuguese are likely next). Country names come from the data, per language.
- Game data (`assets/data/`) is generated by `tools/build_game_data` from `../guessyourflag`. Do not hand-edit
  generated files; change the tool or its override file and rebuild.
- Game logic (question picking, scoring, rewards, streaks, missions) is plain TypeScript with no React in it,
  and has unit tests. Time-based logic takes the clock as a parameter so tests can move time.
- Saves are versioned and migrated. A player must never lose progress, coins or a streak because of an update.
- No other account's branding, names or watermarks anywhere (the videos were inspired by map-quiz accounts;
  the game is ours). Maps only from the Natural Earth data already in the studio.
- Do not add dark patterns: no fake timers, no hidden prices, no tricks to cause accidental ad taps or
  purchases. The stores reject them and players leave.

## Working on your own

- Do not ask questions and do not stop to wait for a reply. Decide as an experienced mobile game designer
  would, record the decision and its reason in `DECISIONS.md`, and continue. Defaults for the open points are
  in `docs/07-BUILD-PLAN.md`.
- Go through all milestones in `docs/07-BUILD-PLAN.md` in order without pausing between them.
- Verify by running the game and looking at it (screenshots, full play sessions), not only by tests passing.
- Review each milestone yourself before starting the next: play a full session as a new player who just came
  from a video, then as a day-7 player, and write down what an experienced mobile game designer would
  criticise (flat moments, unclear next goal, rewards that feel small, anything slow or confusing). A feel
  problem is a bug with the same priority as a crash. Fix it, then move on.
- If something needs a person or an account you don't have, keep the fake service in place, add it to
  `HANDOFF.md`, and carry on with everything else.
- Keep `PROGRESS.md` current (done, next, known issues). After a restart or context reset, read this file,
  `PROGRESS.md` and `DECISIONS.md` and continue from there without asking.

## Commands

| What | Command |
|---|---|
| Install | `npm install` (also copies `canvaskit.wasm` into `public/` for the web preview) |
| Web preview | `npm run web` (or `npx expo export -p web` and serve `dist/` with an SPA fallback) |
| Android / iOS dev build | `npx expo run:android` / `npx expo run:ios` (needs Android Studio / Xcode), or `npx eas-cli build --profile development` |
| Release builds | `npx eas-cli build --profile production --platform all` |
| Tests | `npm test` (game logic, fake clock) |
| Typecheck | `npm run typecheck` |
| Build game data + sounds | `npm run build:data` (needs `../guessyourflag`, Python with shapely + numpy, Node for flags) |
| Balance sim | `npm run sim` (writes `tools/balance_sim/REPORT.md`) |
| Icons / store screenshots | `python3 tools/store_assets/make_icon.py`, `python3 tools/store_assets/compose.py <screenshots dir>` |

Layout: routes in `src/app/`, round + result + home in `src/game/`, pure logic in `src/logic/` (tests in
`src/logic/__tests__`), tuning in `src/config/`, look in `src/theme/`, strings in `src/i18n/strings.ts`, SDKs behind
`src/services/` (fakes by default, real AdMob/RevenueCat in `src/services/real.native.ts` once `src/config/keys.ts` is filled).
On the web build `window.__game` (store) and `globalThis.__round` (current question) exist for automated play sessions.
